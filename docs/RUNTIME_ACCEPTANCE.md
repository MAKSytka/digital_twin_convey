# Runtime-приёмка финальной ветки

Этот документ фиксирует проверки, которые нельзя подтвердить только статическими валидаторами. Все прогоны выполнялись на целевой Ubuntu 24.04 / ROS 2 Jazzy / Gazebo Harmonic после чистой сборки ветки `chore/final-project-packaging`.

## 1. Матрица сингуляризации — принято

Подтверждено на целевой машине:

- чистая сборка создаёт устанавливаемый мир 18×4;
- коробки переходят с инфид-ленты на первую строку матрицы;
- коробки проходят всю матрицу, роликовое горлышко и выходную ленту;
- камера Gazebo поддерживает orbit, pan и zoom;
- `singulation_controller` публикует `MatrixCommand` размером 72;
- `matrix_command_fanout` публикует индивидуальные команды ячеек;
- значения команд находятся в диапазоне 1,00–3,00 м/с;
- рабочая калибровка трения: `mu=0.8`, `mu2=0.2`;
- зазор между инфидом и первой строкой равен 20 мм.

Проверка интерфейса:

```bash
bash scripts/check_v7_control.sh
ros2 topic info /singulator/matrix/command -v
ros2 topic echo /singulator/matrix/command --once
```

## 2. Инфид-сепаратор — принято

Финальная подтверждённая конфигурация:

- 11 сплошных поперечных роликов;
- длина одного ролика 2,480 м;
- радиус 25 мм;
- шаг по X 150 мм;
- продольный физический промежуток 100 мм;
- нижний класс: `projection_x < 0,070 м`;
- безопасный верхний класс: `projection_x >= 0,110 м`;
- вероятность нижнего класса 0,70;
- гравитация демонстрационного мира `12,0 м/с²` вниз;
- коэффициент восстановления `0,00`;
- порог bounce `1,00 м/с`;
- линейное/угловое затухание `0,12 / 0,60`;
- максимальная корректирующая скорость контакта `0,02 м/с`.

Подтверждено на целевой машине:

- на каждом поперечном ряду работает один длинный ролик;
- верхняя и нижняя ветви получают товары;
- мелкие и длинные узкие товары проходят через 100-мм промежутки;
- товары верхнего класса не проваливаются;
- после удара товары быстро стабилизируются;
- на переходах нет устойчивого затора;
- деспавн работает на обеих ветвях.

Увеличенная гравитация и демпфирование являются настройкой демонстрационного мира. Их задача — исключить многократные неестественные отскоки лёгких товаров, а не заменить физическую валидацию реального оборудования.

Проверочный запуск:

```bash
ros2 launch singulator_bringup \
  infeed_size_separator_demo.launch.py \
  spawn_mode:=finite \
  maximum_items:=200 \
  target_rate_boxes_per_sec:=4.0 \
  small_item_probability:=0.70 \
  seed:=42
```

Статическая проверка:

```bash
python3 tools/validate_separator_demo.py
```

## 3. Станция КТЯ runtime v18 — принято

Финальная подтверждённая конфигурация:

- непрерывный цикл `LOAD → CLOSE_GATE → COMPACT → EJECT_ACTIVE → DESPAWN_ACTIVE → POSITION_NEXT → VERIFY_READY → OPEN_GATE → LOAD`;
- два КТЯ одновременно: активный и ожидающий;
- внутренний размер КТЯ 600×400×400 мм;
- товары 35×15×10 … 280×190×145 мм;
- порог заполнения 82%;
- порог максимальной высоты 340 мм;
- камера расположена на 1,10 м над дном КТЯ;
- слабая вибрация 5 Гц, ±1,8 мм;
- основное уплотнение 6,5–9 Гц, ±8 мм, 15 с;
- скорость контактных зон 0,80 м/с;
- две дополнительные сходящиеся направляющие по бокам лотка;
- коридор направляющих сужается примерно с 565 до 400 мм;
- коэффициент восстановления направляющих 0,0;
- центр товара спавнится в диапазоне `Y = ±0,090 м`;
- полная yaw-зависимая поперечная проекция удерживается внутри `Y = ±0,170 м`;
- номинальный запас до внутренних стенок КТЯ составляет 30 мм.

Подтверждено на целевой машине:

- четыре и более последовательных цикла проходят без `ERROR`;
- `position_recovery_failures=0`;
- обе дополнительные направляющие видимы и имеют физические коллизии;
- товары не покидают лоток через боковые стороны;
- все профили товаров попадают внутрь КТЯ;
- направляющие не образуют устойчивого затора у выхода;
- RGB и depth публикуются;
- `/kty/perception/contours`, `/kty/fill/state` и `/kty/flow/state` активны;
- dashboard обновляется;
- заполненная тара удаляется, ожидающая занимает активную позицию.

Запуск:

```bash
bash scripts/build_kty_perception_3d.sh
source install/setup.bash
bash scripts/run_kty_perception_3d.sh
```

Диагностика во втором терминале:

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
bash scripts/check_kty_runtime_v18.sh
```

Статическая проверка:

```bash
python3 tools/validate_kty_runtime_v18.py
```

## 4. Финальный критерий merge

Все три runtime-модуля приняты. Перед слиянием в `main` остаётся выполнить на актуальном commit:

```bash
bash scripts/run_release_checks.sh
```

После успешного статического набора можно открывать финальный PR в `main`, выполнять squash merge, создавать release tag и переходить к безопасной очистке исторических ветвей по `docs/REPOSITORY_CLEANUP.md`.
