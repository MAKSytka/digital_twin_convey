# Runtime-приёмка финальной ветки

Этот документ фиксирует проверки, которые нельзя подтвердить только статическими валидаторами. Все прогоны выполняются на целевой Ubuntu 24.04 / ROS 2 Jazzy / Gazebo Harmonic после чистой сборки ветки `chore/final-project-packaging`.

## Сводный статус

| Узел | Статические проверки | Runtime на финальной ветке | Статус |
|---|---|---|---|
| Матрица 18×4 и роликовое горлышко | пройдены | подтверждён 2026-08-01 | принято |
| Полноширинный инфид-сепаратор | пройдены | подтверждён 2026-08-01 после шага 150 мм и демпфирования | принято |
| Станция КТЯ, runtime v18 | требуется локальный запуск после изменения лотка | предыдущий v18 работал; новые направляющие и spawn-envelope требуют повторного теста | повторная проверка |

## 1. Матрица сингуляризации — принято

Подтверждено на целевой машине:

- чистая сборка создаёт устанавливаемый мир 18×4;
- коробки переходят с инфид-ленты на первую строку матрицы;
- коробки проходят всю матрицу, роликовое горлышко и выходную ленту;
- камера Gazebo поддерживает orbit, pan и zoom;
- `singulation_controller` публикует `MatrixCommand` размером 72;
- `matrix_command_fanout` публикует индивидуальные команды ячеек;
- значения команд находятся в диапазоне 1,00–3,00 м/с;
- рабочая калибровка трения: `mu=0.8`, `mu2=0.2`;
- зазор между инфидом и первой строкой равен 20 мм.

Проверка интерфейса:

```bash
bash scripts/check_v7_control.sh
ros2 topic info /singulator/matrix/command -v
ros2 topic echo /singulator/matrix/command --once
```

## 2. Инфид-сепаратор — принято

Финальная подтверждённая конфигурация:

- 11 сплошных поперечных роликов;
- длина одного ролика 2,480 м;
- радиус 25 мм;
- шаг по X 150 мм;
- продольный физический промежуток 100 мм;
- нижний класс определяется условием `projection_x < 0,070 м`;
- верхний безопасный класс начинается с `projection_x >= 0,110 м`;
- вероятность нижнего класса 0,70;
- гравитация демонстрационного мира `12,0 м/с²` вниз;
- коэффициент восстановления `0,00`;
- порог bounce `1,00 м/с`;
- линейное/угловое затухание `0,12 / 0,60`;
- максимальная корректирующая скорость контакта `0,02 м/с`.

Подтверждено на целевой машине:

- на каждом поперечном ряду работает один длинный ролик;
- верхняя и нижняя ветви получают товары;
- мелкие и длинные узкие товары проходят через 100-мм продольные промежутки;
- товары верхнего класса не проваливаются;
- товары после удара быстро стабилизируются и не совершают серии заметных повторных отскоков;
- на переходах нет устойчивого затора;
- деспавн работает на обеих ветвях.

Увеличенная гравитация и демпфирование являются настройкой демонстрационного мира. Их задача — убрать многократные неестественные подпрыгивания лёгких товаров, а не заменить физическую валидацию реального оборудования.

Проверочный запуск:

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash

ros2 launch singulator_bringup \
  infeed_size_separator_demo.launch.py \
  spawn_mode:=finite \
  maximum_items:=200 \
  target_rate_boxes_per_sec:=4.0 \
  small_item_probability:=0.70 \
  seed:=42
```

Статическая проверка:

```bash
python3 tools/validate_separator_demo.py
```

## 3. Станция КТЯ runtime v18 — повторная проверка после изменения лотка

Новые изменения:

- добавлены две высокие сходящиеся направляющие по бокам наклонного лотка;
- внутренний коридор сужается примерно с 565 до 400 мм;
- направляющие имеют физические коллизии и нулевой коэффициент восстановления;
- центр товара спавнится в диапазоне `Y = ±0,090 м`;
- полная yaw-зависимая поперечная проекция удерживается внутри `Y = ±0,170 м`;
- внутренние стенки КТЯ находятся на `Y = ±0,200 м`, поэтому остаётся номинальный запас 30 мм.

Чистая сборка:

```bash
cd ~/singulator_digital_twin
rm -rf build install log
unset AMENT_PREFIX_PATH
unset CMAKE_PREFIX_PATH
unset COLCON_PREFIX_PATH
source /opt/ros/jazzy/setup.bash
bash scripts/build_kty_perception_3d.sh
source install/setup.bash
```

Запуск:

```bash
bash scripts/run_kty_perception_3d.sh
```

Диагностика во втором терминале:

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
bash scripts/check_kty_runtime_v18.sh
```

Критерии приёмки:

- не менее четырёх различных входов в `LOAD`;
- отсутствует состояние `ERROR`;
- `position_recovery_failures=0`;
- проходят состояния `CLOSE_GATE`, `COMPACT`, `EJECT_ACTIVE`, `DESPAWN_ACTIVE`, `POSITION_NEXT`, `VERIFY_READY`, `OPEN_GATE`;
- обе дополнительные направляющие видны и физически удерживают товары на лотке;
- товары не падают за пределы КТЯ по бокам;
- все десять профилей товаров проходят в КТЯ;
- направляющие не создают устойчивого затора у выхода;
- RGB и depth публикуются;
- `/kty/perception/contours`, `/kty/fill/state` и `/kty/flow/state` активны;
- dashboard обновляется;
- загруженная тара удаляется, следующая тара занимает активную позицию.

Статическая проверка:

```bash
python3 tools/validate_kty_runtime_v18.py
bash scripts/run_release_checks.sh
```

## 4. Финальный критерий merge

Перед слиянием в `main` должны одновременно выполняться:

```bash
bash scripts/run_release_checks.sh
```

и все три runtime-раздела этого документа должны иметь статус `принято`.

После merge выполняется удаление только тех исторических ветвей, которые отмечены в `docs/REPOSITORY_CLEANUP.md` как `safe-ancestor` или `safe-tree-duplicate`.
