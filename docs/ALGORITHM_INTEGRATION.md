# Интеграция алгоритма сингуляризации

## Минимальная ответственность алгоритма

В принятом roller-сценарии на каждом шаге управления алгоритм формирует **72 скорости** и публикует `MatrixCommand`.

```python
ROWS = 18
COLS = 4
speeds = [0.0] * (ROWS * COLS)
speeds[row * COLS + col] = desired_speed_mps
```

Необходимо заполнять:

```text
rows = 18
cols = 4
target_speed_mps = 72 значения
```

Базовый мир `matrix_stream.launch.py` сохраняет историческую конфигурацию 14×4 для простых тестов. Финальная демонстрация жюри запускается через `matrix_stream_roller.launch.py` и расширяет контур до 18×4.

## Рекомендуемая частота

Рабочая частота принятого контроллера — 30 Гц. Команды должны публиковаться непрерывно: при прекращении публикации привод не должен бесконечно сохранять устаревшую команду.

## Этапы подключения

### Этап 1. Равномерный профиль

Все 72 скорости одинаковы. Проверяются размеры сообщения, индексация и направление движения.

### Этап 2. Управление одной строкой

Остальные строки движутся с базовой скоростью, одна строка получает разные скорости левой и правой половины.

```text
левые колонки c00, c01: base + delta
правые колонки c02, c03: base - delta
```

### Этап 3. Плавный профиль по нескольким строкам

Разность скоростей распределяется по соседним строкам, чтобы не создавать резкий скачок скорости и не опрокидывать лёгкие коробки.

### Этап 4. Замкнутый алгоритм

Контроллер получает ID, координаты центра, размеры, yaw и оценку скорости товара. Затем он:

1. сохраняет глобальный порядок товаров;
2. рассчитывает ошибки межтоварных зазоров;
3. формирует требуемые эффективные скорости товаров;
4. определяет пересечение товаров с ячейками;
5. распределяет команды между общими и частными ячейками;
6. ограничивает скорость и ускорение;
7. публикует массив из 72 команд.

Подробное описание: [SINGULATION_CONTROL.md](SINGULATION_CONTROL.md).

## Ограничения команд

В принятом roller-сценарии команды ограничиваются диапазоном `1.0…3.0 м/с`, а ускорение — `6.0 м/с²`. Рабочий алгоритм остаётся forward-only.

Дополнительно ограничиваются:

- изменение скорости между соседними тактами;
- разность скоростей соседних ячеек;
- длительность сильного вращательного воздействия;
- позднее восстановление зазора около выхода.

```python
def clamp(value: float, low: float = 1.0, high: float = 3.0) -> float:
    return max(low, min(high, value))
```

## Проверка публикации

```bash
ros2 topic hz /singulator/matrix/command
ros2 topic echo /singulator/matrix/command --once
ros2 topic echo /singulator/matrix/state --once
```

Для финального roller-сценария ожидаются:

```text
rows: 18
cols: 4
len(target_speed_mps): 72
```

## Интерфейс наблюдений

```text
/singulator/boxes
singulator_interfaces/msg/BoxObservationArray
```

Поток формируется узлом классического машинного зрения по кадрам камеры Gazebo. Нейросетевая модель и Gazebo ground truth для принятия управляющих решений не используются.

## Разделение ответственности

| Цифровой двойник | Алгоритм управления |
|---|---|
| Gazebo-мир и контактная физика | Выбор эффективных скоростей товаров |
| Спавн и удаление коробок | Поддержание глобальной очереди |
| ROS–Gazebo bridge | Управление межтоварными зазорами |
| Fan-out общей команды | Распределение скоростей по ячейкам |
| Камера и CV-наблюдения | Коррекция угла и deadline recovery |
| Диагностические узлы | Метрики качества управления |

Связь между модулями должна проходить через сообщения из `singulator_interfaces`, без встраивания алгоритмической логики в SDF.
