# Цифровой двойник станции операций с КТЯ

## Назначение первой версии

Пакет `kty_station_sim` моделирует полный цикл одной станции:

1. спавн пустого КТЯ на входной контактной зоне;
2. подвод КТЯ к виброплатформе за 2 с;
3. боковое ограничение КТЯ направляющими;
4. хаотичную подачу товара по лотку со средней интенсивностью 1 ед/с;
5. вертикальную регулируемую вибрацию;
6. микропаузу, RGB-D измерение и решение о заполненности;
7. остановку вибрации за 0,5 с до отвода;
8. отвод КТЯ за 1 с и удаление модели из Gazebo.

Геометрия намеренно упрощена. Рольганги и выталкиватели представлены контактными
зонами с задаваемой скоростью поверхности. КТЯ имеет внутренний размер
`600 x 400 x 400 мм`, стенку `3 мм`, открытый верх и массу пустой тары `1,6 кг`.

## Принятые физические параметры

- лоток: `1000 x 600 мм`, угол `32 градусов`;
- нижний край лотка: `420 мм` над внутренним дном КТЯ;
- коэффициент трения всех основных пар: `0,75`;
- материал верхней прокладки виброплатформы: полиуретан TPU-95A;
- движение виброплатформы: вертикальное;
- четыре пружины показаны визуально, физика задаётся призматическим соединением;
- рабочий диапазон: `20-50 Гц`, амплитуда как отклонение от среднего положения
  до `3 мм`;
- безопасное стартовое значение launch-файла: `25 Гц`, `1 мм`.

При `mu=0,75` и угле `32 градусов` плоский товар после полного успокоения может
не продолжить скольжение. Поэтому товар спавнится выше поверхности с ударным
импульсом, а монитор отдельно фиксирует зависание на лотке. Это параметр для
последующей калибровки, а не подтверждённая характеристика реального лотка.

## Запуск

```bash
cd ~/singulator_digital_twin
./scripts/build.sh
source install/setup.bash
./scripts/run_kty_station.sh
```

Параметризованный запуск:

```bash
./scripts/run_kty_station.sh \
  vibration_frequency_hz:=30.0 \
  vibration_amplitude_m:=0.001 \
  product_rate_products_per_s:=1.0 \
  seed:=42
```

Остановка:

```bash
./scripts/stop_kty_station.sh
```

### Управление обзорной камерой Gazebo

В мире явно загружается GUI-плагин `MinimalScene`, поэтому обзорная камера
управляется мышью независимо от фиксированной RGB-D камеры машинного зрения:

- левая кнопка и перетаскивание — панорамирование;
- средняя кнопка и перетаскивание — вращение вокруг сцены;
- `Shift` + левая кнопка и перетаскивание — альтернативное вращение;
- правая кнопка и перетаскивание или колесо — приближение и удаление;
- правая кнопка по объекту → `Move to` — центрирование на выбранном узле.

Нижняя панель `World control` показывает кнопку Play/Pause. Мир настроен на
автоматический запуск, а launch-файл дополнительно повторяет команду
`pause: false`, чтобы узлы с `use_sim_time=true` не зависали при неподвижном
`/clock`.

Проверка, что симуляционное время растёт:

```bash
gz topic -e -t /world/kty_station/stats -n 1
```

Ручной запуск мира, если он был поставлен на паузу пользователем:

```bash
gz service \
  -s /world/kty_station/control \
  --reqtype gz.msgs.WorldControl \
  --reptype gz.msgs.Boolean \
  --timeout 3000 \
  --req 'pause: false'
```

## Автомат состояний

```text
WAIT_EMPTY_KTY
  -> POSITION_KTY
  -> CLAMP
  -> LOAD
  -> VIBRATE
  -> SETTLE
  -> SCAN
      -> VIBRATE, если высота ниже порога
      -> EJECT_PREP, если достигнут порог
  -> EJECT
  -> WAIT_EMPTY_KTY
```

При критической неисправности автомат переходит в `FAULT`, закрывает шторку,
останавливает ленты и вибрацию. Сброс:

```bash
ros2 service call /kty/station/reset std_srvs/srv/Trigger '{}'
```

## Интерфейс машинного зрения

Входы:

```text
/kty/camera/image         sensor_msgs/msg/Image
/kty/camera/depth_image   sensor_msgs/msg/Image
/kty/camera/camera_info   sensor_msgs/msg/CameraInfo
```

Выход:

```text
/kty/perception/contours
singulator_interfaces/msg/KtyProductContourArray
```

Для каждого видимого товара публикуются:

- устойчивый `track_id` между последовательными проверками;
- полигон видимой верхней области в системе `kty_inner`;
- высота верхней поверхности;
- оценка видимой площади;
- доступность четырёх боковых направлений и оценка зазора.

Разделение соприкасающихся товаров выполняется комбинацией карты глубины,
локальных максимумов distance transform и watershed. Полностью одинаковые
товары с одной копланарной поверхностью и без видимого шва принципиально могут
быть неразличимы одним верхним RGB-D сенсором. Это должно отражаться в метриках,
а не скрываться использованием ground truth.

Ground truth Gazebo применяется только для проверки алгоритма и не поступает на
вход детектора.

## Контролируемые неисправности

`kty_safety_monitor` формирует `/kty/fault` для сценариев:

- товар выпал из КТЯ;
- товар завис на лотке;
- КТЯ отсутствует или не находится на активной позиции;
- превышена масса `35 кг`;
- потерян обзор RGB-D камеры;
- товар продолжает двигаться после остановки вибрации.

## Метрики

Результаты каждого цикла сохраняются в:

```text
/tmp/kty_station_metrics/cycle_XXXXXX/
```

Файлы:

- `summary.json` — заполнение, высота, пустоты, время успокоения и точность зрения;
- `timeseries.csv` — состояние, высота, заполнение и максимальная скорость;
- `product_displacements.csv` — перемещение каждого товара.

Коэффициент заполнения и пустоты рассчитываются воксельной моделью по
независимому ground truth. Точность зрения считается по сопоставлению центров
детекций с фактическими позами Gazebo: precision, recall, F1 и средняя ошибка.

## Ограничения первой версии

- картон, полиуретан и товары моделируются жёсткими телами;
- деформация стенок КТЯ и повреждение товара не моделируются;
- доступные боковые поверхности пока представлены четырьмя направлениями, а не
  полной 3D-сеткой поверхности;
- реальные коэффициенты трения и параметры вибратора требуют калибровки;
- перед инженерными выводами нужно провести серии минимум по 100 случайных
  заполнений для каждой пары частота/амплитуда.
