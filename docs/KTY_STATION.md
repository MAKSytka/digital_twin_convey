# Цифровой двойник станции операций с КТЯ

## Назначение

Пакет `kty_station_sim` моделирует полный цикл одной станции:

1. спавн пустого КТЯ на входной зоне;
2. подвод КТЯ к виброплатформе за 2 с;
3. боковое ограничение направляющими;
4. хаотичную подачу товара по лотку со средней интенсивностью 1 ед/с;
5. вертикальную регулируемую вибрацию;
6. микропаузу, RGB-D измерение и решение о заполненности;
7. остановку вибрации за 0,5 с до отвода;
8. отвод КТЯ за 1 с и удаление модели из Gazebo.

Геометрия намеренно упрощена. КТЯ имеет внутренний размер
`600 × 400 × 400 мм`, стенку `3 мм`, открытый верх и массу пустой тары
`1,6 кг`.

## Принятые параметры

- лоток: `1000 × 600 мм`, угол `32°`;
- нижний край лотка: `420 мм` над внутренним дном КТЯ;
- коэффициент трения основных пар: `0,75`;
- верхняя прокладка платформы: полиуретан TPU-95A;
- движение виброплатформы: вертикальное;
- четыре пружины показаны визуально, физическая степень свободы задаётся
  призматическим соединением;
- рабочий диапазон: `20–50 Гц`, амплитуда до `3 мм` как отклонение от
  среднего положения;
- стартовая конфигурация: `25 Гц`, `1 мм`.

При `mu=0,75` и угле `32°` полностью успокоившийся плоский товар может не
продолжить скольжение. Это параметр для последующей калибровки.

## Архитектура runtime v2

Предыдущая версия связывала весь цикл с поступлением `/kty/world/poses`. При
отсутствии или несовместимости моста поз автомат оставался в `POSITION_KTY`, а
спавнер товаров никогда не включался.

В runtime v2 транспорт разделён на два уровня:

- `TrackController` задаёт скорость видимым контактным зонам;
- встроенный в модель КТЯ `VelocityControl` получает
  `/kty/carrier/cmd_vel` и гарантирует подвод/отвод независимо от настройки
  трения контактной зоны.

Фактическая поза остаётся диагностикой. Если она поступает, контроллер проверяет
центрирование. Если поток поз недоступен, после детерминированного двухсекундного
перемещения автомат продолжает цикл и отмечает использование fallback в поле
`reason`.

Высокочастотный узел `kty_vibration_driver` работает с периодом `2 мс`:

```text
/station_controller
    -> /kty/carrier/cmd_vel
    -> /kty/station/state

/kty_vibration_driver (500 Гц)
    -> /kty/carrier/cmd_vel_filtered
    -> /kty/platform/cmd_pos_filtered

ros_gz_bridge
    -> Gazebo /kty/carrier/cmd_vel
    -> Gazebo /kty/platform/cmd_pos
```

Это отделяет частоту автомата состояний от частоты дискретизации вибрации.

## Чистая сборка КТЯ

После изменения сообщений или Python entry points выполняйте целевую сборку:

```bash
cd ~/singulator_digital_twin
bash ./scripts/build_kty_station.sh
```

Скрипт очищает и пересобирает вместе:

```text
singulator_interfaces
kty_station_sim
```

Это предотвращает ситуацию, когда Python-узлы обновлены, а терминал продолжает
использовать старый rosidl type support.

## Запуск

```bash
cd ~/singulator_digital_twin
bash ./scripts/run_kty_station.sh
```

Параметризованный запуск:

```bash
bash ./scripts/run_kty_station.sh \
  vibration_frequency_hz:=30.0 \
  vibration_amplitude_m:=0.001 \
  product_rate_products_per_s:=1.0 \
  seed:=42
```

Окно `rqt_image_view` теперь выключено по умолчанию, чтобы ошибка GUI не
останавливала основной сценарий. Включение:

```bash
bash ./scripts/run_kty_station.sh vision_gui:=true
```

Остановка:

```bash
bash ./scripts/stop_kty_station.sh
```

## Диагностика

В новом терминале обязательно загрузите окружение:

```bash
cd ~/singulator_digital_twin
source /opt/ros/jazzy/setup.bash
source install/setup.bash
bash ./scripts/check_kty_station.sh
```

Запускной скрипт, выполненный в другом процессе, не может изменить окружение
уже открытого диагностического терминала.

Проверка пользовательского типа:

```bash
ros2 interface show singulator_interfaces/msg/KtyGroundTruthArray
```

Канонический типизированный реестр:

```bash
ros2 topic echo /kty/ground_truth/registry --once
```

Диагностический JSON-зеркальный топик стандартного типа:

```bash
ros2 topic echo /kty/ground_truth/registry_json --once
```

Состояние автомата:

```bash
ros2 topic echo /kty/station/state
```

Частота фильтрованной команды:

```bash
ros2 topic hz /kty/carrier/cmd_vel_filtered
```

Подробный runbook: [`KTY_RUNTIME_V2.md`](KTY_RUNTIME_V2.md).

## Автомат состояний

```text
WAIT_EMPTY_KTY
  -> POSITION_KTY
  -> CLAMP
  -> LOAD
  -> VIBRATE
  -> SETTLE
  -> SCAN
       -> VIBRATE, если высота ниже порога
       -> EJECT_PREP, если достигнут порог
       -> повтор проверки при единичной потере кадра
  -> EJECT
  -> WAIT_EMPTY_KTY
```

В состояниях `LOAD` и `VIBRATE` публикуется
`/kty/product_spawner/enabled=true`. Спавнер создаёт модели вида:

```text
kty_product_c000001_p000001
```

## Машинное зрение

Входы:

```text
/kty/camera/image         sensor_msgs/msg/Image
/kty/camera/depth_image   sensor_msgs/msg/Image
/kty/camera/camera_info   sensor_msgs/msg/CameraInfo
```

Выход:

```text
/kty/perception/contours
singulator_interfaces/msg/KtyProductContourArray
```

Для каждого видимого товара публикуются:

- устойчивый `track_id`;
- полигон видимой верхней области;
- высота верхней поверхности;
- видимая площадь и confidence;
- доступность четырёх боковых направлений и оценка зазора.

Ground truth Gazebo используется для верификации и метрик, но не является
входом детектора.

## Контролируемые неисправности

`kty_safety_monitor` обрабатывает:

- товар выпал из КТЯ;
- товар завис на лотке;
- КТЯ отсутствует или смещён при доступной диагностике поз;
- превышена масса `35 кг`;
- потерян RGB-D обзор;
- товар продолжает двигаться после остановки вибрации.

Отсутствие всего потока поз отключает только зависящие от него проверки и не
блокирует транспорт. Единичная потеря RGB-D кадра является предупреждением;
контроллер переводит станцию в `FAULT` после трёх последовательных неудачных
проверок.

## Метрики

Результаты цикла сохраняются в:

```text
/tmp/kty_station_metrics/cycle_XXXXXX/
```

Файлы:

- `summary.json`;
- `timeseries.csv`;
- `product_displacements.csv`.

Оцениваются коэффициент заполнения, максимальная высота, пустоты, время
успокоения, перемещения товаров и точность машинного зрения.

## Ограничения

- картон, полиуретан и товары моделируются жёсткими телами;
- деформация стенок КТЯ и повреждение товара не моделируются;
- коэффициенты трения и параметры вибратора требуют экспериментальной
  калибровки;
- статический GitHub CI не заменяет запуск контактной физики на Ubuntu 24.04 с
  ROS 2 Jazzy и Gazebo Harmonic.
