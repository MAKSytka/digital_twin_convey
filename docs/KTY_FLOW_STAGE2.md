# KTY flow stage 2: плавное движение, загрузка, вибрация и despawn

Этот сценарий добавляет к принятому smoke baseline полный воспроизводимый цикл
одной КТЯ без старого автомата, perception, safety и метрик.

## Цикл

```text
WAIT_SERVICES
  -> SPAWN_KTY
  -> APPROACH
  -> LOAD
  -> SETTLE
  -> VIBRATE
  -> OUTFEED
  -> OUTFEED_HOLD
  -> DESPAWN
  -> COMPLETE
```

По умолчанию:

1. создаётся динамический открытый КТЯ `kty_flow_container`;
2. КТЯ перемещается от `x=-1,25 м` до центра платформы за 3 с;
3. на лотке последовательно создаются шесть фиксированных товаров;
4. товары скользят и падают внутрь КТЯ;
5. контроллер проверяет их реальные позы через `/world/kty_flow/pose/info`;
6. загруженный КТЯ вибрирует 5 с;
7. после вибрации реальные позы товаров считываются повторно;
8. КТЯ и товары перемещаются до `x=1,35 м`;
9. после визуальной паузы все семь динамических моделей удаляются.

## Плавность движения

Транспорт пока задаётся сервисом Gazebo `/world/kty_flow/set_pose`. Для удаления
видимых рывков:

- частота обновления КТЯ повышена с 5 до 20 Гц;
- используется fifth-order smootherstep;
- скорость и ускорение равны нулю в начале и конце траектории;
- товары корректируются с отдельной частотой 8 Гц, чтобы не запускать семь
  процессов `gz service` на каждом кадре;
- между коррекциями товары продолжают взаимодействовать с КТЯ через контактную
  физику.

Профиль интерполяции:

```text
s(t) = 6t^5 - 15t^4 + 10t^3
```

## Вибрация

После того как все товары подтверждены внутри КТЯ, выполняется отдельное
состояние `VIBRATE`:

```text
длительность: 5,0 с
частота:       5,0 Гц
амплитуда:     ±2,0 мм
обновление:    30 Гц
```

Амплитуда плавно нарастает и снижается по огибающей, поэтому начало и окончание
фазы не создают одиночного скачка позы.

## Сборка

```bash
cd ~/singulator_digital_twin
chmod +x scripts/*kty_flow.sh tools/validate_kty_flow.py
python3 tools/validate_kty_flow.py
bash ./scripts/build_kty_flow.sh
```

## Запуск

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
bash ./scripts/run_kty_flow.sh
```

Непрерывное повторение:

```bash
bash ./scripts/run_kty_flow.sh auto_repeat:=true
```

Изменение плавности:

```bash
bash ./scripts/run_kty_flow.sh \
  pose_update_hz:=30.0 \
  approach_duration_s:=4.0 \
  outfeed_duration_s:=4.0
```

## Диагностика

Во втором терминале:

```bash
cd ~/singulator_digital_twin
source /opt/ros/jazzy/setup.bash
source install/setup.bash
bash ./scripts/check_kty_flow.sh
```

Состояние можно наблюдать отдельно:

```bash
ros2 topic echo /kty/flow/state
```

Повтор цикла после `COMPLETE` или `ERROR`:

```bash
ros2 service call /kty/flow/restart std_srvs/srv/Trigger '{}'
```

## Имена моделей

```text
kty_flow_container
kty_flow_product_01
...
kty_flow_product_06
```

После `COMPLETE` эти модели должны отсутствовать.

## Критерий приёмки

1. движение КТЯ визуально плавное на подводе и отводе;
2. шесть товаров падают внутрь КТЯ;
3. `inside_products` достигает 6;
4. состояние `VIBRATE` длится около 5 секунд;
5. вибрация начинается и заканчивается без скачка;
6. загруженный КТЯ уходит вместе с товарами;
7. все динамические модели удаляются;
8. `check_kty_flow.sh` завершается `KTY flow diagnostics: OK`.

## Ограничения

- транспорт и вибрация пока задаются позами, а не приводами лент и платформы;
- товары на отводе перемещаются как зарегистрированная группа;
- используется фиксированный набор из шести товаров;
- контроллер работает по wall time и не зависит от `/clock`;
- машинное зрение добавляется следующим отдельным PR.
