# Демонстрация входного размерного сепаратора

## Назначение

Стенд показывает предварительный механический отсев товаров, которые небезопасно подавать на крупноячеистую матрицу сингуляризации. Входная линия, верхний выход и нижний выход имеют ширину 2,5 м. Скорость движущихся поверхностей по умолчанию равна 2 м/с.

После роликового экрана поток разделяется:

- товар, чья продольная опорная проекция перекрывает зазор между роликами, продолжает движение по верхней ветви;
- товар с продольной проекцией менее 70 мм проваливается между соседними роликами на нижнюю приёмную ленту.

Коробки автоматически удаляются после достижения конца соответствующей ветви.

## Геометрия непрерывных роликов

Экран состоит из 11 поперечных роликов. Каждый поперечный ряд представлен одним сплошным роликом, а не набором отдельных мини-дисков.

Параметры одного ролика:

- длина рабочей поверхности — 2,480 м;
- радиус — 25 мм;
- контактный диаметр — 50 мм;
- ось вращения — Y;
- одно `revolute`-соединение;
- один `gz::sim::systems::JointController`.

Продольный межосевой шаг увеличен до 150 мм. Чистый промежуток между соседними роликами:

```text
150 мм - 50 мм = 100 мм
```

Программный порог нижнего класса сохранён на уровне 70 мм. Поэтому товар, рассчитанный для нижней ветви, получает до 30 мм дополнительного физического запаса относительно отверстия.

Чтобы отверстие 100 мм не совпадало с нижней границей верхнего класса, безопасный верхний порог увеличен до 110 мм. Товары с продольной проекцией 70–110 мм не генерируются в release-сценарии: эта область считается защитным диапазоном.

Поперечных отверстий внутри одного ряда нет. Каждый вал имеет одну непрерывную контактную поверхность по всей ширине потока.

Скорость поверхности рассчитывается по радиусу 25 мм:

```text
omega = v / r = 2 / 0.025 = 80 rad/s
n = omega * 60 / (2*pi) = 763.9 rpm
```

## Переходы на выходные конвейеры

После увеличения шага до 150 мм роликовый экран стал длиннее. Входная и верхняя выходная ленты смещены, нижняя приёмная лента увеличена до 1,7 м, а боковые ограждения и щёки роликового экрана расширены.

Переходы настроены следующим образом:

- входная лента → первый ролик: 9 мм;
- последний ролик → верхняя выходная лента: 1 мм;
- нижняя приёмная лента → нижний выход: 1 мм;
- принимающие выходные ленты расположены на 4 мм ниже предыдущей поверхности;
- скорость всех транспортных поверхностей — 2 м/с.

## Правило размерного класса

Для основания `L × W`, повёрнутого на угол `yaw`, вычисляются проекции:

```text
projection_x = |L cos(yaw)| + |W sin(yaw)|
projection_y = |L sin(yaw)| + |W cos(yaw)|
```

Маршрут определяется продольной проекцией:

```text
projection_x < 0.070 м  -> LOWER
projection_x >= 0.110 м -> UPPER
```

Диапазон 70–110 мм оставлен как защитная зона между классами. Товары верхней ветви не генерируются в этой пограничной области.

Длинные и узкие товары нижнего класса создаются преимущественно поперёк движения. Тогда их короткая сторона образует продольную проекцию менее 70 мм и с заметным запасом попадает в 100-мм промежуток между соседними роликами.

## Профили генерируемых коробок

Вероятность класса `LOWER` в release-сценарии равна 70%. Это позволяет на короткой демонстрации хорошо видеть работу нижней ветви, деспавнера и пограничных профилей.

### Нижняя ветвь

- `micro_parcel` — компактный товар от 35×15×10 мм;
- `long_narrow` — длинный узкий товар, ориентированный почти поперёк потока;
- `flat_strip` — плоская длинная упаковка с малой продольной проекцией;
- `tall_slender` — высокая узкая коробка;
- `near_cutoff` — продольная проекция 55–69 мм для проверки границы.

### Верхняя ветвь

- `medium_carton`;
- `large_carton`;
- `long_parcel`;
- `flat_panel`;
- `tall_carton`;
- `square_carton`.

## Масса и демпфирование ударов

Масса оценивается как сумма массы содержимого и картонной оболочки:

```text
mass = bulk_density * volume
     + cardboard_areal_density * surface_area
```

Для устранения многократных подпрыгиваний лёгких товаров используется отдельный демонстрационный профиль контакта:

```text
gravity_z_mps2                         = -12.0
spawn_clearance_m                      = 0.001
box_restitution                        = 0.00
bounce_capture_velocity_mps            = 1.00
linear_velocity_decay                  = 0.12
angular_velocity_decay                 = 0.60
contact_max_correcting_velocity_mps    = 0.02
```

Коэффициент восстановления равен нулю, поэтому контакт не должен возвращать коробке заметную вертикальную энергию. Повышенный порог bounce подавляет отскок при большинстве штатных столкновений, а усиленное линейное и угловое затухание быстрее успокаивает лёгкие и высокие упаковки.

Гравитация `12,0 м/с²` является намеренной настройкой демонстрационной модели, а не заявлением о физической гравитации реального склада. Она используется для устойчивого визуального поведения товаров при падении через роликовый экран.

## Сборка и запуск

После изменения SDF-модели требуется пересборка затронутых пакетов. Для финальной проверки рекомендуется чистая сборка:

```bash
cd ~/singulator_digital_twin
rm -rf build install log
source /opt/ros/jazzy/setup.bash
bash scripts/build.sh
source install/setup.bash
```

Запуск:

```bash
ros2 launch singulator_bringup \
  infeed_size_separator_demo.launch.py \
  seed:=42
```

Конечный тест:

```bash
ros2 launch singulator_bringup \
  infeed_size_separator_demo.launch.py \
  spawn_mode:=finite \
  maximum_items:=200 \
  target_rate_boxes_per_sec:=4.0 \
  small_item_probability:=0.70 \
  seed:=42
```

## Проверка

```bash
python3 tools/validate_separator_demo.py
```

При runtime-прогоне нужно подтвердить:

1. на каждом поперечном ряду виден один длинный ролик;
2. межосевой шаг равен 150 мм, а чистый продольный промежуток — 100 мм;
3. около 70% созданных товаров относятся к ожидаемому маршруту `LOWER`;
4. длинные узкие товары поперечной ориентации надёжно проваливаются между соседними роликами;
5. товары верхнего класса с `projection_x >= 110 мм` остаются на верхней ветви;
6. товары после удара не совершают серии заметных повторных отскоков;
7. верхний и нижний стыки не образуют устойчивый затор;
8. `remove_failures=0`;
9. число моделей после конечной серии уменьшается до штатного уровня.
