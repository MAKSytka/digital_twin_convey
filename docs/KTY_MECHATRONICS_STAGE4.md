# KTY stage 4: физическая механика и непрерывная смена тары

Этот этап заменяет покадровое перемещение через `set_pose` физическими механизмами
Gazebo. Команды положения и скорости поступают через постоянный
`ros_gz_bridge`; во время движения не создаются процессы `gz service`.

## Принятые решения

- входная подача КТЯ: линейный толкатель;
- транспорт после входа: физические приводные ролики;
- одновременно присутствуют активный и ожидающий КТЯ;
- во время загрузки тара зажимается двумя боковыми губками;
- позиционирование по X выполняет выдвижной упор;
- стопор лотка — одна поворотная створка с осью вдоль верхнего ребра;
- слабая вибрация при загрузке: 8 Гц, ±0,5 мм;
- уплотнение: 18 Гц, ±3 мм, 8 секунд;
- закрытие створки: заполненный объём ≥70% или высота ≥280 мм;
- критерий должен выполняться 0,5 секунды.

## Механическая структура

```text
infeed queue
  -> pusher
  -> powered infeed rollers
  -> retractable X locator
  -> active rollers on Z vibration deck
  -> side clamps
  -> powered outfeed rollers
```

В мире находится 17 цилиндрических роликов:

```text
7 infeed + 3 active + 7 outfeed
```

Центральные ролики, боковые зажимы и продольный упор установлены на общей
виброплатформе. Поэтому движение платформы передаётся таре и товарам через
контактную физику, а не изменением мировой позы КТЯ.

## Почему добавлен выдвижной продольный упор

Одних роликов недостаточно для устойчивого позиционирования с допуском ±5 мм.
Перед подачей нового КТЯ упор поднимается. Тара доезжает до него на малой
скорости, ролики останавливаются, затем закрываются боковые зажимы. Перед
отводом заполненной тары упор опускается.

## Непрерывный цикл

```text
LOAD
  -> CLOSE_GATE
  -> COMPACT
  -> EJECT_ACTIVE
  -> POSITION_NEXT
  -> VERIFY_READY
  -> OPEN_GATE
  -> LOAD
```

Во время `LOAD` створка открыта, а КТЯ получает слабую вибрацию. Когда оценка
заполнения достигает порога, створка закрывается. Подача товаров не
останавливается: товары накапливаются на лотке.

Во время `COMPACT` активная тара зажата и вибрирует 8 секунд. Затем:

1. зажимы открываются;
2. продольный упор опускается;
3. активные и выходные ролики отводят заполненный КТЯ;
4. упор поднимается;
5. толкатель вводит ожидающий КТЯ на входные ролики;
6. ролики подают его к упору;
7. проверяются положение, скорость, зажимы, камера и освобождение опасной зоны;
8. создаётся новый ожидающий КТЯ;
9. створка открывается, накопленные товары падают в новую тару.

## Оценка заполненного объёма

`kty_fill_estimator` обрабатывает depth-карту независимо от instance
segmentation. Для каждого пикселя внутренней области вычисляется высота над
дном. Объём оценивается интегрированием вертикальных столбцов:

```text
V = Σ(height_pixel × area_pixel)
fill_ratio = V / (0,60 × 0,40 × 0,40)
```

Топик:

```text
/kty/fill/state
```

Содержит:

```text
estimated_volume_m3
capacity_m3
fill_ratio
maximum_height_m
valid_depth_fraction
camera_ok
```

## Проверка готовности нового КТЯ

Створка открывается только после одновременного выполнения:

```text
|x - x_target| ≤ 5 мм
скорость по X ≤ 0,02 м/с
боковые зажимы закрыты
продольный упор поднят
камера исправна
оценка заполнения новой тары ≤15%
предыдущий КТЯ вышел из опасной зоны
условия сохраняются ≥0,3 с
```

## Критерии приёмки

1. КТЯ перемещаются непрерывно, без покадровой телепортации.
2. Во время движения отсутствуют частые вызовы `/set_pose`.
3. Одновременно существуют активный и ожидающий КТЯ.
4. При заполнении створка закрывается.
5. Товары физически накапливаются на закрытом лотке.
6. В `COMPACT` заметно движение платформы и перераспределение товаров.
7. Заполненный КТЯ уезжает на роликах.
8. Толкатель подаёт ожидающий КТЯ.
9. Створка открывается только после `VERIFY_READY`.
10. Диагностика завершается `KTY mechatronics diagnostics: OK`.

## Ограничения этапа

- физические параметры роликов, PID виброплатформы и усилия зажимов требуют
  настройки на целевой машине;
- входной поток временно подобран так, чтобы накопительная часть лотка не
  переполнялась;
- instance segmentation пока остаётся алгоритмом предыдущего этапа;
- улучшенная 3D-сегментация, OBB, нормали, OCCLUDED-треки и grasp candidates
  реализуются следующим stacked PR.
